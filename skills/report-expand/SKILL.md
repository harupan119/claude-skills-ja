# report-expand — レポートを実質的な内容追加で増量する

既存レポート本文を、**実質的な内容追加**で目標倍率まで増量する。文の引き延ばし・水増し・定型評価語の挿入はしない。複数の追加ブロックをサブエージェントで並列生成し、main（このセッション）が統合・整合・レビューを担う。

提出先に書式規約（大学の作成要領、学会のテンプレート、社内フォーマット等）がある場合は、**その規約を先に読む**。本スキルは規約の上に重ねる増量手順であり、規約と衝突したら規約が優先する。

## 大原則（違反厳禁）

- **実質追加のみ。** 既存の主張を言い換えて伸ばさない。新しい節・表・導出・理論的射程・図の読み取りなど、情報量が増える追加だけを行う。
- **register を壊さない。** だ・である調（academic）なら最後まで維持。仕上げのAI臭除去は `humanizer-ja-modes` の **academic モード**（`modes/academic/MODE.md`）を使う。casual モードの体温注入・ですます化は**適用しない**。
- **数値は実測のみ。** 元データ（CSV等）に存在する値だけを使う。捏造・概算の独自生成をしない。サブエージェントにも実測値を渡し、新しい数値を作らせない。統合後に `scripts/check_numbers.py` で出所を機械的に照合する（§7）。
- **既存の表・図・コード・確定数値は改変しない。** 追加は本文・新規表のみ。
- **章節番号と相互参照の整合は main が統合時に担保する。** 新章挿入による繰り下げ、本文中の「4.6 の通り」等の参照追従を必ず修正。

## 倍率の決め方

- 密度の限界がある。むやみに3倍以上を狙うと教科書の丸写し・脱線に陥り、内容が薄まる。**2.2〜2.5倍が実質追加で保てる現実的な上限**の目安。
- 元の本文文字数（コード・付録除外）を測り、目標倍率から増分を逆算してブロックに配分する。

## ワークフロー

### 1. 現状把握
- 対象 .md を読む。元の本文文字数を測る（コードブロック除外・空白除去、下記スクリプト）。
- 増量前の本文を `report.orig.md` のように別名で保存する。§5 の差分レビューと §7 の数値照合で使う。
- 元データ（CSV・測定結果）の所在と実値を把握。追加で使える事実を洗い出す。

### 2. ブロック設計
- 各章ごとに「何を足すか」を増分目標つきで割り付ける（例：序論に研究背景＋評価指標、考察に計算量の数式導出、新章に理論的射程、結果に未提示の指標表）。
- 近接ブロックはクラスタ化してサブエージェント数を絞る（cold start 削減）。
- **同じ章の中で前後に並ぶブロックは、別々のエージェントに分けない。** 並列生成は、前に書かれた本文を見ずに書くので段落間のつながりが落ちる。LongWriter（Bai et al. 2024）の比較では、各段を並列に生成した場合、前段までの本文を渡して逐次生成した場合より一貫性（Coherence）の評価が6%下がった。並列にするのは、互いに参照しない章どうし（例：序論の背景と、結果の未提示指標表）に限る。
- 各ブロックに**何を新しく足すか**を1行で書いておく（例：「計算量 O(n log n) の導出」）。ここが書けないブロックは、言い換えで字数を埋めることになるので設計から外す。

### 3. サブエージェント並列生成
- general-purpose を並列起動。各エージェントに渡す：担当ブロックの指示／既存該当章の要点／**厳守ルール**（register・用語固定・数値捏造禁止・AI臭禁止）／**使ってよい実測値**。
- 出力は「この位置に入る本文断片（.md）」。節番号は振らせず main が振る。小見出しの番号も main 側で付与。
- AI臭の事前禁止を必ず明記：「することができる」「〜ではなく、〜だ」構文の乱用、三語並列、全角ダッシュ（——）、定型評価語、前置きクリシェ。
- **厳守ルールはプロンプトの冒頭に置き、末尾でもう一度短く繰り返す。** 長い入力の中ほどに置いた情報は使われにくい（Liu et al. 2023 "Lost in the Middle"：関連情報が文脈の先頭か末尾にあるとき性能が最も高く、中ほどで大きく落ちる）。既存章の要点や実測値の表を間に挟むと、ルールがその中ほどに埋もれる。
- 担当ブロックの直前・直後の既存段落は、要約ではなく**原文のまま**渡す。つなぎの文を書くのに必要なのは要約ではなく実際の語句である。

### 4. 統合（main）
- 各断片を所定位置に挿入。新章挿入に伴う**章番号・節番号の繰り下げ**と、本文中の相互参照を修正。
- 参考文献は規約上「番号なし見出し」。章番号付与時に整合を取る。
- 目標倍率に届かなければ、図表の本文言及（規約上も必須）や未提示データの読み取りなど**実質的な追記**で埋める。水増しはしない。

### 5. レビュー（専用エージェント）
- 専用レビューエージェントを並列起動する。各々に対象 .md・元データCSV・（あれば）学術文章の原則をまとめた資料の場所を渡す：
  - **consistency-checker**：章節連番、相互参照の指す先、数値の本文内一致、CSV実測との一致、用語統一、図表・キャプション整合。
  - **logic-reviewer**：新旧節の接続・重複・矛盾、主張→根拠→機序の流れ、節間トランジション。
  - **technical-reviewer**：計算量・数式・近似・方法論・定義と数値の整合、引用の妥当性。
  - **writing-reviewer**：簡潔性・明瞭性・academic tone・AI臭（B2否定対比/B8 tell）。
- これらが使えない環境では general-purpose に上記4観点を一括レビューさせる（cold start 節約のフォールバック）。
- 指摘（重大度つき）を受け、main が修正。

**LLM レビューの偏りを前提に組む。** このスキルは「長くする」ことが目的なので、LLM レビュアーの偏りがちょうど悪い方向に効く。

- **長いほうを良いと判定しやすい（冗長性バイアス）。** MT-Bench の検証（Zheng et al. 2023）では、箇条書きの各項目を情報を足さずに言い換えて先頭に重ねただけの回答を、元の回答より良いと判定した割合が GPT-3.5・Claude-v1 で91.3%、GPT-4 で8.7%だった。言い換えによる水増しを、レビュアーが自発的に見抜くとは限らない
- **自分と同系統のモデルが書いた文を高く評価しやすい（自己選好）。** Panickssery et al. 2024 は、LLM が自分の出力を他者の出力と見分けられること、その識別能力が強いほど自分の出力を高く採点することを示した。生成と同じモデルのレビューで「問題なし」と返っても、品質の証拠としては弱い
- **外部の手がかり無しに見直させても、推論の誤りは直らない。** Huang et al. 2024 は、正解ラベルなどの外部フィードバックを与えない自己修正が推論課題の正答率を改善せず、下げる場合もあることを示した

そこでレビューは次の形にする。

1. **差分でレビューさせる。** 完成稿だけを渡さず、元の本文と増量後の本文の両方を渡す。何が足されたかを本人に探させない
2. **追加分の主張を棚卸しさせる。** 追加された段落ごとに、含まれる主張を1文1事実に分解させ（FActScore, Min et al. 2023 の原子的事実の考え方）、各事実を「新規（出所：CSV の列名・元本文の節・参考文献）」「既存の言い換え（元本文の該当箇所）」「出所なし」の3つに分類させる。「既存の言い換え」だけで構成された段落は削る。「出所なし」は根拠を足すか削る
3. **合否は機械検査で決める。** 数値の出所（`check_numbers.py`）、字数、禁止語は§6・§7のスクリプトで判定する。LLM レビューは見落としを拾う補助であり、「指摘ゼロ」を合格の根拠にしない

### 6. AI臭チェック＋AI度判定（main）
- `humanizer-ja-modes` の **academic モード**を適用。下記スクリプトで機械検出し、casual 化はせず検出パターンのみ書き換える。register維持・接続詞の裸消し禁止・段落結束は MODE.md に従う。
- 表紙メタデータの太字ラベル（科目名・氏名等）は対象外。接続詞・否定文も「乱用」でなければ放置。
- **書き換え後、`humanizer-ja-modes` の `references/ai-score-rubric.md` で AI度を採点する。** スコア・判定ラベル・根拠（どのパターンがどこに）を出し、academic では register違反/段落結束崩れも加点。**目安：AI度41以上（混在）なら、強tellを潰してもう一周。提出は40以下を目標**にする。

### 7. 字数・数値の出所の検証
- 再カウントして目標倍率到達を確認。用語禁止語（科目固有：例「素朴版」「学生証番号」）の不在も確認。
- `scripts/check_numbers.py` で、本文中の数値のうち元の本文・CSV のどこにも無いものを洗い出す。出た数値は1件ずつ「どの実測値から、どう計算したか」を説明できることを確認し、説明できないものは消す。比や差のような導出値は出て当然なので、その場合は本文に計算の元（「表2の 130.2 ms を 12.5 ms で割ると」など）を書く。

```sh
python3 scripts/check_numbers.py report.md --source report.orig.md data/*.csv
# L42: 10.4	…約10.4倍に増えた。
# 出所不明の数値: 1 件
```

章節番号・図表番号・式番号・「4.6 の通り」の類は数値の主張ではないので除外している。増量前の本文は `report.orig.md` などに必ず残しておく（このスクリプトと§5の差分レビューの両方で使う）。

## 文字数カウント（コード除外・再現用）

```sh
python3 -c "
import re
s=open('report.md').read()
body=re.sub(r'\`\`\`.*?\`\`\`','',s,flags=re.DOTALL)  # フェンスドコード除外
nows=re.sub(r'\s','',body)                            # 空白除去
print('本文:',len(nows),'字  倍率:',round(len(nows)/BASE,2))  # BASE=元の本文字数
"
```

## AI臭の機械チェック（本文のみ）

```sh
python3 -c "
import re
s=open('report.md').read()
body=re.sub(r'\`\`\`.*?\`\`\`','',s,flags=re.DOTALL)
pats={
 '全角ダッシュ':'——','することができ':'することができ',
 'でしょう調':'(と言えるでしょう|ではないでしょうか|ではないだろうか)',
 'です・ます混入':'(です。|ます。|ません。|でしょう。)',
 '定型評価語':'(浮き彫り|注目に値|画期的|多面的|包括的|計り知れ|今後の展開が注目)',
 '太字ラベル箇条書き':r'^\s*[-*]\s*\*\*[^*]+\*\*[:：]',
}
for n,p in pats.items():
    h=[i+1 for i,l in enumerate(body.split(chr(10))) if re.search(p,l)]
    print(n, len(h), h[:10])
"
```

だ・である調レポートでは「です・ます混入」「でしょう調」「することができ」は0が正常。太字ラベルは表紙メタデータ以外0。

## 関連

- 提出先の書式規約（構成・体裁・引用の作法）。**先に読む**。本スキルはその上に重ねる。規約をスキル化している場合はそちらを優先する。
- 学術文章の原則をまとめたローカル資料があれば、レビュー担当のサブエージェントに読ませる（任意）。
- AI臭除去（仕上げ）：`humanizer-ja-modes` の academic モード（`modes/academic/MODE.md`、casual化しない）。構造的tell・禁止語は同スキルの `references/banned-ja.md`。AI度の採点は `references/ai-score-rubric.md`。

## 根拠文献

いずれも無料で公開されている原著論文。数値は各論文の測定時点のモデルでの値である。

- Bai et al. *LongWriter: Unleashing 10,000+ Word Generation from Long Context LLMs.* 2024, arXiv:2408.07055. 長文を「計画（段落ごとの要点と字数）→段落ごとに生成」に分けると長さの指定に従えるようになる。段落を並列に生成すると、逐次生成より一貫性が6%下がる。分割生成では前段の内容の言い直しや要約の挟み込みが起きやすい
- Liu et al. *Lost in the Middle: How Language Models Use Long Contexts.* TACL, arXiv:2307.03172 (2023). 関連情報が入力の先頭か末尾にあるとき性能が最も高く、中ほどにあると大きく下がる
- Zheng et al. *Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena.* NeurIPS 2023, arXiv:2306.05685. 位置・冗長性・自己強化の各バイアスを測定。言い換えで水増しした回答を良いと判定する割合は GPT-3.5・Claude-v1 で91.3%
- Panickssery, Bowman, Feng. *LLM Evaluators Recognize and Favor Their Own Generations.* 2024, arXiv:2404.13076. 自己識別の能力と自己選好の強さに線形の相関
- Huang et al. *Large Language Models Cannot Self-Correct Reasoning Yet.* ICLR 2024, arXiv:2310.01798. 外部フィードバックなしの自己修正は推論性能を改善せず、下げる場合がある
- Min et al. *FActScore: Fine-grained Atomic Evaluation of Factual Precision in Long Form Text Generation.* EMNLP 2023, arXiv:2305.14251. 長文を原子的事実に分解し、出所で支持される割合を測る。長文は支持される事実とされない事実が混在するため、全体を一括で可否判定するのは不十分

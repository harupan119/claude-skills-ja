# calendar-scheduling — 空き時間を出して予定を重複なく入れる

## いつ使うか

- 日程候補をメールや返信文に入れるとき
- ユーザーの空き時間を確認するとき
- 表・画像・メールの日程を **カレンダーに登録する** とき → 「予定を登録するとき」へ

## 手順（空き時間の提示）

### Step 1: 全カレンダーを取得する

**必ず `list_calendars` から始める。** Inboxだけ見ない。

```
list_calendars() → 全カレンダーIDを取得
```

よくあるカレンダー：バイト、大学、Inbox、日本の祝日、タスク

### Step 2: 全カレンダーのイベントを並行取得する

対象期間の全カレンダーを **同時に** 取得する。

```
list_events(calendarId=バイトID, ...)
list_events(calendarId=大学ID, ...)
list_events(calendarId=InboxID, ...)
```

### Step 3: 曜日を正確に計算する

**日付から曜日を導くとき、必ず基準日から数えて確認する。**

**使う年の基準日を1つ確定させてから数える。** 例（2026年）：

- 2026-01-01 = 木曜
- 2026-04-01 = 水曜

ズレが起きやすいので、提示する日付には必ず曜日を併記し、自分で検算する。

### Step 4: ブロック時間を整理する

取得したイベントをリスト化：
- 日付・曜日・開始〜終了時刻・イベント名・カテゴリ（バイト/サークル/大学等）

### Step 5: バッファルールを適用する

**各予定の開始1時間前から終了まではブロック。**

例：
- バイト 16:00〜 → 15:00以降はNG
- サークル 19:00〜 → 18:00以降はNG
- 1時間のミーティングなら、終了時刻がバッファ開始以前になるよう逆算

### Step 6: 空きスロットを列挙する

ブロック時間を除いた候補を曜日つきで提示。

```
例：
- 4/23（木）19:00〜 ✓
- 4/29（水）17:00〜 ✓（サークル19:00のため18:00終了まで）
```

## 予定を登録するとき

読み取りと違い、書き込みは失敗が「重複」として残る。登録前に必ず Step A〜D を通す。

### Step A: 曜日から年を確定する

表や画像の日付には曜日が併記されていることが多い。`7/28(火)` の曜日が一致する年に登録する。基準日から数えて検算し、確定した年を本文に書く。

### Step B: 重複チェックは「時間枠」で行う（名前検索に頼らない）

**`q=` のキーワード検索だけで重複を判定してはいけない。** 同じ予定が複数の表記で入っている。

実際に踏んだ表記ゆれの型（名前は伏せて構造だけ示す）：

| 実体 | 登録されている表記 |
|---|---|
| 定例の練習 | `Orchestra` / `orchestra `（末尾スペース）/ `オーケストラ` |
| 関連する別予定 | `Orchestra合宿` / `Orchestra-打ち上げ` |

`q=Orchestra` で検索するとカタカナ表記が漏れ、同じ枠に2件作ってしまう。**英字とカタカナ、大文字小文字、末尾スペースの4方向にずれる**と考えておく。

正しい手順：**タイトル無指定**で対象期間を全カレンダー分取得し、開始時刻が一致する予定を照合する。

```
list_events(calendarId=各ID, timeMin=期間開始, timeMax=期間終了,
            singleEvents=true, orderBy=startTime)
→ 登録したい各枠と同じ開始時刻の既存予定がないか目で確認
```

### Step C: 表記・場所・登録先を既存に合わせる

過去の同種予定を1件読んで、タイトル表記／場所欄の使い方／登録先カレンダーを踏襲する。

- 定例のサークル活動 → primary カレンダー、タイトルは英字表記で統一、場所欄に会場名
- アルバイト → 専用カレンダー

### Step D: 全件を表で提示して承認を取ってから書く

作成する予定を「日時・場所」の表にして提示し、承認を得てから実行する。過去日を含めるかもここで確認する。削除・上書きも同様に承認を取る。

### 重複が見つかった場合

どちらを残すかはユーザーに選ばせる。残す側が決まったら、削除後に期間を再取得して各枠1件になったことを確認し、その出力を報告に含める。

- [ ] 曜日は正確か（計算して確認したか）？
- [ ] 各予定の1時間前バッファを適用したか（空き時間提示時）？
- [ ] イベント名から種別を決めつけていないか（英字の略称を別カテゴリと誤認する等）？
- [ ] メモリのルールを盲信せず、実際のカレンダーを優先したか？
- [ ] **登録時**：タイトル無指定で期間全件を取得し、時間枠で重複照合したか？
- [ ] **登録時**：表記ゆれ（英字／カタカナ／大小文字／末尾スペース）を潰したか？
- [ ] **登録時**：書き込み・削除の前に一覧を提示して承認を取ったか？
- [ ] **登録後**：期間を再取得して、意図した件数になったか確認したか？
